# Design decisions through the DDIA lens

The current TiKV implementation uses TxnKV only. Metadata, revision and authority currently expire after 500 ms, reserving 500 ms for buffered publication within the healthy-system one-second visibility target; immutable bytes are reused by content hash after the selected revision is validated. Writes retain their original version preconditions and publish atomically. [Cache protocol](CONTENT_HASH_CACHE.md), [one-second design](../../dfs/design/ONE_SECOND_VIEW.md), [current benchmark](../../dfs-bench/docs/RESULTS.md).

Chapter references use the first edition of *Designing Data-Intensive Applications*. These are application design choices, not claims that the book endorses this implementation. [Reading map](READING_GUIDE.md).

## D30: partial batch drains and acknowledged directory overlays

When a new file still fits the one-MiB limit but its batch does not, retain that file locally and publish the other files. The sealed subset and request identity survive uncertain replies; synchronization drains both the selected and retained files. This avoids converting a capacity boundary into several synchronous writes. A successful directory create can be added to an unexpired cached projection, preserving its deadline and journal cursor. Publication acknowledgement establishes that directory's identity; it does not establish observation of intervening external changes.

This applies DDIA chapter 7's distinction between the dependencies of one acknowledged transaction and a complete observed history. Tests exercise an external change before the local directory acknowledgement and require later replay to retain both. [Design](../../dfs-bench/docs/WRITE_PATH_REWORK.md#capacity-and-directory-overlay-follow-up), [client implementation](../src/mount_cache.rs), [TiKV tests](../../dfs-bench/results/buffer-04-tikv-tests.log), [FDB tests](../../dfs-bench/results/buffer-04-fdb-tests.log), [RocksDB tests](../../dfs-bench/results/buffer-04-rocks-tests.log).

## Publication boundaries and replication

Chapters 5 and 6 distinguish replication from partitioning. Replicated storage provides durable copies; an application’s transaction dependencies decide which writers conflict. TiKV frontends can prepare work concurrently, but shared tenant journal/state still makes unrelated publications compete. FDB now uses direct native transactions; its filesystem state/journal records still create a shared tenant dependency. [Concrete root examples](ROOT_BOUNDARIES.md) explain file, directory, project and tenant boundaries.

## Optimistic concurrency and cached observations

Chapter 7 explains conditional publication and transactions; chapters 8 and 9 separate failure ambiguity from stale observations. A one-second cache horizon never authorizes overwriting a changed version. Storage validates current authority and the original expected revision during publication. Lost replies retain request identities and outcomes so a retry cannot append twice. A timeout is not proof of non-publication.

Chapters 3 and 7 also separate immutable layout from reader semantics. A read selects a coherent generation. An existing descriptor can select a newer generation after metadata expiry. Unlinked identities and delayed requests still need retention; safe reclamation is unfinished.

## Derived indexes and measurement

Chapters 11 and 12 describe indexes as derived data. Filesystem state and the indexing event publish together; index application and visibility follow asynchronously. Search validates candidate authority and versions against filesystem state. Search visibility is distinct from fsync durability.

Chapter 1 requires workload-specific measurements. Warm scans exercise the cached client path; cold client reads expose RPC and backend work; writes expose publication and indexing work. [The clean benchmark method](../../dfs-bench/docs/METHOD.md) fixes hardware and separates extraction, filesystem, search and catch-up phases.

## D32: authorized content-hash reuse and bounded read batches

Implemented across RocksDB, TiKV and FDB. Metadata selects an authorized revision within one second. Manifest references select immutable hashes; previous hashes are hints, never authority. Concurrent misses share bounded server snapshot contexts, and replies are checked again before installation. [Implementation and sequence diagram](CONTENT_HASH_CACHE.md).

## D33: transactional key hints and immutable-key prefetch

Bounded hints store credential/principal key addresses, never authorization results. Each operation rereads the current session and credential inside the transaction. TiKV also retains prefetched immutable-key values or absence until the corresponding staged write checks them, avoiding a redundant read without dropping conflicts. This applies DDIA chapter 7 to the precise dependency set. [Design and measured iterations](../../dfs-bench/docs/WRITE_PATH_REWORK.md#grouping-transactional-reads), [engine](../src/engine.rs), [transaction adapter](../src/txn_store.rs), [revocation tests](../tests/engine.rs), [absence-conflict tests](../tests/txn_storage.rs).

## D34: bulk byte encoding with unchanged bytes

Use Serde byte slices for payloads while preserving Bincode field order, lengths and enum discriminants. DDIA chapter 4 distinguishes an encoding implementation from an incompatible format migration. Golden old/new encoding tests and bounded malformed-length rejection are required. [Design](../../dfs-bench/docs/WRITE_PATH_REWORK.md#byte-encoding-without-a-format-migration), [codec tests](../tests/codec.rs), [full measured results](../../dfs-bench/docs/FULL_RESULTS.md).

## D35: directory changes share the bounded publication batch

Buffer-09 buffers new directory identities and directory attributes alongside new file bodies, with unchanged 64-node/one-MiB limits. Parents precede descendants; existing directory attributes retain original revision and entry fences. This removes directory boundaries as mandatory network commits while preserving transactional namespace validation. DDIA chapter 7 supplies the transaction model; chapter 8 supplies the stable retry-identity requirement. [Design and verification status](../../dfs-bench/docs/WRITE_PATH_REWORK.md#directory-creation-and-attribute-coalescing), [client](../src/mount_cache.rs), [validation](../src/engine/mutations.rs), [tests](../tests/buffered.rs).

## D36: original acceptance times and bounded transfer scheduling

Buffer-10 records the first acceptance time of each pending node. Removing a confirmed subset cannot make an unrelated younger record appear older, and edits/retries cannot renew that record's deadline. Client/frontend receive windows are explicitly bounded, while TiKV prefetch groups are larger within the same key/value admission limits. This applies DDIA chapters 8–9 to deadline ownership and chapters 3–4 to batching and transfer costs. [Design, limits and tests](../../dfs-bench/docs/WRITE_PATH_REWORK.md#pending-record-age-and-bounded-transfer-scheduling), [client](../src/mount_cache.rs), [transaction grouping](../src/engine/mutations.rs), [measurement settings](../../dfs-bench/docs/METHOD.md).

## D37: Separate publication capacity from individual I/O limits

Buffer-11 uses a 128-node/two-MiB pending publication bound across all three mounts, while retaining one-MiB individual I/O and four-MiB RPC message limits. Capacity drains preserve original per-record ages and exact sealed retries. Larger batches amortize fixed publication work, at the cost of more volatile pending bytes and a wider conflict set. This does not resolve the shared tenant journal's contention.
